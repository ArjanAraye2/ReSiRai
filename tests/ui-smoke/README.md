# آزمون‌های دودِ UI (نگهبان‌ها)

هر صفحه یک «نگهبان» است: یک باگِ واقعیِ رخ‌داده را بازسازی و راستی‌آزمایی
می‌کند. عنوانِ سند (`document.title`) نتیجه را اعلام می‌کند: `SMOKE-N-PASS ...`.

| صفحه | نگهبانِ چه چیزی | باگِ مبدأ |
|---|---|---|
| `smoke2.html` | رندرِ جدولِ بازبینی + پنلِ فاکتورها + دیکته | دودِ DOM اولیه |
| `smoke3.html` | پنلِ «آزمایشات»: کارت‌ها، وضعیتِ بازه، تکهٔ برگه | طراحیِ پنلِ آزمایشات |
| `smoke4.html` | **نبودِ حلقهٔ observer** میانِ پنلِ آزمایشات و مالی | هَنگِ «در حال دریافت اطلاعات…» (۱۴۰۵/۰۷/۱۱) |
| `smoke5.html` | **نگهبانِ fetch**: مهمان/صف/واردشده بدونِ هَنگ | هَنگِ کلیک روی بیمار (۱۴۰۵/۰۷/۱۱) |
| `smoke8.html` | **بخش‌هایِ مراجعه**: آکاردئونِ تک‌باز، تیک/لغو، «لطفاً تکمیل کنید»، «✓ ثبت شد»، تکرارپذیرها با منبعِ «تکرارشده»، بازخوانیِ دادهٔ ثبت‌شده، دیالوگِ «+ بخشِ دیگر» | طراحیِ بخش‌هایِ مراجعه |

`smoke5` کدِ واقعیِ نگهبانِ fetch را از `index.html` استخراج می‌کند
(`verify.ps1` → `gate-under-test.js`) تا هرگز نسخهٔ کهنه آزموده نشود.

## اجرا
```powershell
powershell -File tests\verify.ps1          # بیلد + تست‌ها + آماده‌سازیِ دودها
powershell -File tests\ui-smoke\serve.ps1  # سرورِ استاتیک روی 8765
```
سپس در مرورگر: `http://localhost:8765/smoke2.html` تا `smoke5.html` —
عنوانِ هر صفحه باید `SMOKE-N-PASS` باشد.

## قاعده
هر باگِ UI که رفع می‌شود، یک دودِ نگهبان هم باید داشته باشد (یا دودِ موجود
گسترش یابد) تا بازگشتش بی‌صدا نماند.
